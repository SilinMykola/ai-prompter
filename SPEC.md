# AI Prompter — спецификация v1.1

Локальное веб-приложение, которое слушает звук вкладки Chrome со звонком (Google Meet и др.), показывает живую расшифровку речи собеседника на языке оригинала (немецкий или английский) и русский перевод по предложениям. По запросу подсказывает ответ: короткий или подробный.

Этот документ — задание для Claude Code. Реализуй всё из разделов 1–9. Раздел 10 — критерии приёмки, раздел 11 — что делать НЕ нужно.

Имя репозитория и пакета: `ai-prompter`.

## 1. Цель и сценарий

Пользователь участвует в звонке на немецком или английском, его родной язык — русский. Главная потребность: **точно понять, что спрашивает собеседник**. Подсказки ответа вторичны.

Сценарий:

1. Пользователь запускает приложение локально (`npm run dev`) и открывает `http://localhost:5175` в Chrome в отдельном окне рядом со звонком.
2. Выбирает язык звонка, провайдера и модели, при желании вводит контекст звонка, нажимает «Начать».
3. Chrome показывает диалог выбора вкладки. Пользователь выбирает вкладку со звонком и включает галочку «Также поделиться звуком вкладки».
4. На экране сразу идёт текст оригинала, под каждым законченным предложением появляется русский перевод.
5. При необходимости пользователь нажимает у конкретной реплики «Коротко» или «Подробно» и получает подсказку ответа.
6. По кнопке «Стоп» захват прекращается, по закрытии вкладки всё исчезает.

## 2. Стек

- **Монорепозиторий** с npm workspaces: `server/` и `web/`, общие типы в `shared/`.
- **Язык:** TypeScript везде, `strict: true`.
- **Сервер:** Node.js 20+, Express (раздача собранного фронта в проде и `GET /api/config`), `ws` для WebSocket. LLM-клиенты: `@google/genai` (Gemini) и `@anthropic-ai/sdk` (Claude). К Deepgram подключаться по WebSocket напрямую через `ws` (без SDK).
- **Фронт:** Vite + React 18. Без UI-библиотек и без стейт-менеджеров, обычный CSS.
- **Запуск:** одна команда `npm run dev` поднимает сервер (порт 8787) и Vite (порт 5175, проксирует `/ws` и `/api` на сервер). `npm run build && npm start` — сборка и запуск одним процессом на 8787.
- **Тесты:** Vitest, только для чистой логики (разделы 6.2 и 7.1).

Перед написанием кода сверь с актуальной документацией:

- параметры Deepgram streaming API (`/v1/listen`) и список языков режима `language=multi` у Nova-3;
- актуальные идентификаторы моделей Gemini (быстрая Flash-Lite/Flash и более сильная) и Claude (Haiku и Sonnet);
- актуальный JS SDK Gemini и его способ стриминга; как отключить или минимизировать «thinking» у Flash-моделей.

Если что-то в этой спецификации расходится с документацией — следуй документации и отметь расхождение в README.

## 3. Конфигурация

Файл `.env` в корне (в репозиторий положить `.env.example`, сам `.env` — в `.gitignore`):

```
DEEPGRAM_API_KEY=
DEEPGRAM_MODEL=nova-3

# Провайдер по умолчанию: gemini | anthropic
LLM_PROVIDER=gemini

GEMINI_API_KEY=
# Список моделей через запятую; первая — быстрая (перевод), вторая — сильная (подробные подсказки)
GEMINI_MODELS=<быстрая Flash-модель>,<сильная модель>

ANTHROPIC_API_KEY=
ANTHROPIC_MODELS=claude-haiku-4-5-20251001,claude-sonnet-5-5

PORT=8787
```

В `.env.example` подставь реальные актуальные идентификаторы моделей Gemini после сверки с документацией.

Правила:

- Ключи живут только на сервере и никогда не попадают во фронт.
- Сервер слушает только `127.0.0.1`.
- Обязателен `DEEPGRAM_API_KEY` и ключ хотя бы одного LLM-провайдера. Провайдер без ключа считается недоступным и не показывается в интерфейсе.
- Если `LLM_PROVIDER` указывает на провайдера без ключа, по умолчанию берётся первый доступный, в лог пишется предупреждение.
- При старте без обязательных ключей сервер завершает работу с понятным сообщением, какой переменной не хватает.

`GET /api/config` возвращает (без ключей):

```json
{
  "defaultProvider": "gemini",
  "providers": [
    { "id": "gemini", "label": "Gemini", "models": ["...", "..."] },
    { "id": "anthropic", "label": "Claude", "models": ["...", "..."] }
  ]
}
```

## 4. Архитектура

```
Вкладка со звонком
      │  (звук вкладки, getDisplayMedia)
      ▼
web (React) ── MediaRecorder, webm/opus, чанки 250 мс ──► WebSocket /ws
                                                              │
                                                        server (Node)
                                                              │
                              ┌───────────────────────────────┤
                              ▼                               ▼
                    Deepgram streaming STT              LlmProvider (интерфейс)
                    (interim + final текст)             ├─ GeminiProvider
                              │                         └─ AnthropicProvider
                              │                         (перевод, подсказки; стриминг)
                              └──────────► события ◄──────────┘
                                              │
                                              ▼
                                        web: карточки реплик
```

Один браузерный WebSocket = одна сессия звонка. На каждую сессию сервер открывает одно соединение с Deepgram.

## 5. Фронтенд

### 5.1. Экран подготовки

При загрузке запросить `/api/config`.

- **Источник звука:** переключатель «Вкладка Chrome» (по умолчанию) / «Микрофон». Микрофон нужен для телефона на громкой связи и для тестов.
- **Язык звонка:** «Немецкий» / «Английский» / «Авто (DE+EN)». По умолчанию — «Немецкий».
- **Провайдер:** выпадающий список доступных провайдеров. Если доступен один — показать его как текст без списка.
- **Модель перевода** и **модель подсказок:** два выпадающих списка из моделей выбранного провайдера. По умолчанию: перевод — первая модель списка, подсказки — последняя. При смене провайдера оба списка сбрасываются на значения по умолчанию.
- **Контекст звонка:** textarea, необязательное. Плейсхолдер: «Кто звонит, куда, зачем. Например: запись к терапевту; техническое интервью на Magento-разработчика». Нигде не сохраняется.
- **Мои данные:** textarea, необязательное. Плейсхолдер: «Имя, дата рождения, страховая, профессия и стек — то, о чём могут спросить».
- Кнопка **«Начать»**.

В `localStorage` этого браузера сохраняются (чтение и запись в try/catch): «Мои данные», источник звука, язык, провайдер и обе модели. Если сохранённые провайдер или модель больше недоступны — молча взять значения по умолчанию.

### 5.2. Захват звука

Режим «Вкладка Chrome»:

```ts
const stream = await navigator.mediaDevices.getDisplayMedia({ video: true, audio: true });
```

- `video: true` обязателен, иначе Chrome не покажет диалог. Видеодорожку не использовать и не отправлять; не останавливать её до конца сессии.
- Если в `stream.getAudioTracks()` пусто — остановить все дорожки и показать ошибку: «Звук не захвачен. Выберите вкладку Chrome и включите „Также поделиться звуком вкладки“». Кнопка «Попробовать снова».
- Из аудиодорожек собрать новый `MediaStream` и отдать в `MediaRecorder` с `mimeType: 'audio/webm;codecs=opus'`, `timeslice` 250 мс.
- Событие `ended` на любой дорожке (пользователь нажал «Закрыть доступ») = корректная остановка сессии.

Режим «Микрофон»: `getUserMedia({ audio: true })`, дальше то же самое.

### 5.3. Экран звонка

- **Шапка:** индикатор состояния (`подключение…` / `слушаю` / `собеседник говорит` / `переподключение…` / `остановлено`), выбранный язык, провайдер и модель перевода мелким текстом, кнопка «Стоп».
- **Лента реплик**, новые снизу, автопрокрутка вниз. Автопрокрутка отключается, если пользователь прокрутил вверх, и включается обратно при возврате в самый низ.
- **Карточка реплики** (одна на предложение):
  - оригинал — крупно (не меньше 20px), контрастно;
  - под ним перевод — чуть мельче, другим цветом; пока перевод не пришёл — тонкий индикатор загрузки;
  - две кнопки подсказки: **«Коротко»** и **«Подробно»** (раздел 7.3). Подсказка стримится в блок под переводом. Повторное нажатие любой из кнопок заменяет предыдущую подсказку этой карточки.
- **Горячие клавиши** для последней законченной реплики: `1` — «Коротко», `2` — «Подробно». Не срабатывают, когда фокус в поле ввода.
- **Текущая незаконченная фраза** показывается внизу ленты отдельной «живой» карточкой: финальная часть текста обычным цветом, interim-часть — серым. Перевода у неё нет.
- Тёмная тема по умолчанию. Вёрстка должна нормально работать в узком окне шириной от 420px (окно стоит сбоку от звонка).
- Никаких модальных окон и всплывающих уведомлений во время звонка: ошибки показываются строкой в шапке.

### 5.4. Устойчивость

- Обрыв браузерного WebSocket: до 5 попыток переподключения с задержкой 0.5 → 1 → 2 → 4 → 8 с, запись звука при этом не останавливать, лента реплик сохраняется на экране. После 5 неудач — статус «остановлено» и кнопка «Начать заново».
- Сообщение `error` от сервера — показать текст в шапке.

## 6. Сервер: распознавание

### 6.1. Подключение к Deepgram

URL: `wss://api.deepgram.com/v1/listen`, заголовок `Authorization: Token <DEEPGRAM_API_KEY>`.

Параметры запроса:

| Параметр | Значение |
|---|---|
| `model` | из `DEEPGRAM_MODEL` |
| `language` | `de`, `en` или `multi` (для «Авто») |
| `interim_results` | `true` |
| `smart_format` | `true` |
| `punctuate` | `true` |
| `endpointing` | `300` |
| `utterance_end_ms` | `1000` |
| `vad_events` | `true` |

`encoding` и `sample_rate` не указывать: звук идёт в контейнере webm, Deepgram определяет формат сам.

- Бинарные сообщения от браузера пересылаются в Deepgram как есть. Пока соединение с Deepgram не открыто, чанки складываются в буфер (не больше 5 с звука) и отправляются после открытия.
- Каждые 5 с тишины от браузера отправлять `{"type":"KeepAlive"}`.
- При остановке сессии отправить `{"type":"CloseStream"}` и закрыть соединение.
- При обрыве соединения с Deepgram — переподключение с той же задержкой, что в 5.4; клиенту отправить `status: "reconnecting"`. После переподключения Deepgram нужен заголовок webm-контейнера, поэтому сервер просит клиент перезапустить `MediaRecorder` сообщением `restart_recorder`.

Распознавание тоже спрятать за интерфейсом `SttProvider` (одна реализация — Deepgram), чтобы позже можно было добавить другую.

### 6.2. Сборка предложений (чистая логика, покрыть тестами)

Модуль `server/src/sentences.ts`, без ввода-вывода.

- Вход: поток результатов распознавания (`transcript`, `is_final`, `speech_final`) и события `UtteranceEnd`.
- Результаты с `is_final: false` дают только interim-текст для живой карточки.
- Результаты с `is_final: true` дописываются в буфер финального текста.
- Из буфера вырезаются законченные предложения: граница — `.`, `?`, `!` или `…`, за которыми идёт пробел или конец буфера. Не считать границей точку после цифры в середине числа или даты (`3.5`, `12.10.2026`) и после типичных сокращений (`z.B.`, `Dr.`, `Nr.`, `bzw.`, `ca.`, `e.g.`, `Mr.`, `Mrs.`).
- По `speech_final: true` или `UtteranceEnd` остаток буфера сбрасывается как предложение, даже без знака в конце.
- Предложение длиннее 300 символов без границы принудительно режется по последней запятой или пробелу.
- Пустые строки и строки из одних знаков препинания отбрасываются.
- Каждое предложение получает `id` (возрастающее целое в пределах сессии).

Тесты Vitest: обычные предложения, вопрос, число с точкой, дата, сокращение, сброс по `speech_final`, слишком длинная фраза, пустой ввод.

## 7. Сервер: перевод и подсказки

### 7.1. Интерфейс провайдера

Вся работа с LLM идёт через один интерфейс; остальной код сервера не знает, какой провайдер выбран.

```ts
// server/src/llm/types.ts
export interface LlmRequest {
  model: string;
  system: string;
  user: string;
  maxTokens: number;
  temperature?: number;
  signal?: AbortSignal;
}

export interface LlmProvider {
  readonly id: 'gemini' | 'anthropic';
  readonly models: string[];
  /** Стримит текст ответа кусками. Ошибки API бросает как LlmError. */
  stream(req: LlmRequest): AsyncIterable<string>;
}
```

- Реализации: `server/src/llm/gemini.ts`, `server/src/llm/anthropic.ts`. Реестр `server/src/llm/index.ts` создаёт провайдеров по наличию ключей и отдаёт их по `id`.
- `LlmError` несёт поле `kind: 'rate_limit' | 'auth' | 'timeout' | 'other'`. Ошибки обоих SDK приводятся к нему.
- Промпты лежат в `server/src/prompts.ts` и общие для всех провайдеров.
- У Gemini для быстрых моделей отключить или минимизировать «thinking», если модель это позволяет: здесь важна задержка.
- Сессия получает провайдера и модели из сообщения `start`. Сервер проверяет, что провайдер доступен и модели есть в его списке; иначе `error` и закрытие сессии.
- README: раздел «Как добавить провайдера» (реализовать интерфейс, зарегистрировать, добавить переменные в `.env.example`).

Тесты Vitest: реестр (провайдер без ключа недоступен, запасной провайдер по умолчанию) и проверка `start` — на заглушке провайдера, без сети.

### 7.2. Перевод

Запускается для каждого законченного предложения сразу, запросы идут параллельно (не ждать предыдущий перевод). Модель — «модель перевода» сессии.

- `maxTokens`: 300, `temperature`: 0.
- System prompt (по смыслу, формулировку можно улучшить):

  > Ты синхронный переводчик разговора. Переводи реплику собеседника на русский язык. Отвечай только переводом, без кавычек, пояснений и вариантов. Сохраняй имена, числа, даты, названия документов и учреждений точно. Немецкие официальные термины, у которых нет точного русского аналога (Überweisung, Krankenkasse, Termin и т. п.), переводи и оставляй оригинал в скобках. Технические термины программирования (index, cron, deployment и т. п.) не переводи. Если реплика обрывочная или распознана с ошибкой — переведи как есть, ничего не додумывая.
  >
  > Контекст звонка: {callContext или «не указан»}

- В пользовательском сообщении: до 4 предыдущих предложений как контекст (с пометкой, что их переводить не нужно) и текущее предложение для перевода.
- Данные из поля «Мои данные» в запрос перевода НЕ включать.
- Токены перевода стримятся клиенту по мере поступления.
- Ошибка или таймаут 10 с: одна повторная попытка, затем клиенту уходит `translation_error` для этого `id`; карточка показывает «перевод не получен» и кнопку «повторить».
- Ошибка `rate_limit`: повтор через 2 с, а в шапке показать «лимит запросов провайдера» — на бесплатном уровне Gemini это ожидаемая ситуация.

### 7.3. Подсказка ответа

Запускается только по запросу клиента для конкретного `id`, в одном из двух режимов. Модель — «модель подсказок» сессии. Ответ стримится.

Общий контекст обоих режимов: до 6 предыдущих предложений, реплика, на которую нужен ответ, контекст звонка, «Мои данные».

**Режим `short` («Коротко»)** — готовая фраза, которую можно сказать.

- `maxTokens`: 200.
- System prompt (по смыслу):

  > Ты помогаешь человеку ответить в разговоре на иностранном языке. Его уровень языка средний. Предложи один короткий, вежливый и простой ответ на реплику собеседника — не длиннее двух предложений, на языке реплики. Затем с новой строки дай русский перевод этого ответа. Используй данные пользователя, если они нужны для ответа. Если данных для ответа нет, оставь место в квадратных скобках, например [дата рождения]. Ничего не выдумывай.

**Режим `detailed` («Подробно»)** — шпаргалка по существу вопроса: что такое упомянутый термин и что стоит сказать в ответ. Пример: собеседник спрашивает про индексы в Magento — подсказка кратко объясняет, что это и как создаётся свой индексатор.

- `maxTokens`: 500.
- System prompt (по смыслу):

  > Ты помогаешь специалисту ответить на вопрос собеседника в разговоре на иностранном языке. Дай шпаргалку, которую можно прочитать за несколько секунд:
  > 1. Первая строка — суть ответа одним предложением на языке реплики.
  > 2. Затем 3–5 коротких пунктов на языке реплики: ключевые факты, шаги или термины, которые стоит назвать. Каждый пункт — не длиннее 12 слов, точные названия (классы, файлы, команды) приводи как есть.
  > 3. Затем строка «RU:» и то же самое по-русски, так же кратко.
  > Никаких вступлений и заключений. Если вопрос не технический, а бытовой — дай 2–3 пункта о том, что нужно сообщить. Если не уверен в факте — не включай его. Учитывай профессию и стек пользователя из его данных.

Ошибки подсказки: `hint_error` с `id`; карточка показывает «подсказка не получена».

## 8. Протокол WebSocket (`/ws`)

Типы сообщений описать в `shared/protocol.ts` и использовать с обеих сторон.

Клиент → сервер:

| Сообщение | Поля | Когда |
|---|---|---|
| `start` (JSON) | `language: "de" \| "en" \| "multi"`, `provider`, `translationModel`, `hintModel`, `callContext`, `profile` | первым сообщением после открытия |
| бинарные данные | чанк webm/opus | во время записи |
| `hint` (JSON) | `id: number`, `mode: "short" \| "detailed"` | нажата «Коротко» или «Подробно» |
| `retranslate` (JSON) | `id: number` | нажато «повторить» |
| `stop` (JSON) | — | нажато «Стоп» |

Сервер → клиент (всё JSON):

| Сообщение | Поля |
|---|---|
| `status` | `state: "connecting" \| "listening" \| "speaking" \| "reconnecting" \| "stopped"` |
| `interim` | `finalText: string`, `interimText: string` — содержимое живой карточки |
| `sentence` | `id`, `text`, `language?` |
| `translation_delta` | `id`, `delta` |
| `translation_done` | `id` |
| `translation_error` | `id` |
| `hint_start` | `id`, `mode` — клиент очищает блок подсказки |
| `hint_delta` | `id`, `delta` |
| `hint_done` | `id` |
| `hint_error` | `id` |
| `restart_recorder` | — |
| `error` | `message` (на русском, понятно человеку) |

Состояние `speaking` выставляется по событию `SpeechStarted` от Deepgram, `listening` — по `UtteranceEnd`. Новый запрос `hint` для того же `id` отменяет предыдущий незавершённый (через `AbortSignal`).

## 9. Приватность (жёсткие требования)

- Ничего не сохранять на диск: ни звук, ни расшифровку, ни переводы, ни контекст.
- В логи сервера не писать текст реплик, переводов, подсказок, контекста и профиля. Логировать только события (подключение, ошибки, коды, провайдер, модель) и длительности.
- Вся информация о сессии хранится в памяти и удаляется при закрытии WebSocket.
- Единственное постоянное хранилище — `localStorage` браузера (раздел 5.1).
- Никакой аналитики, телеметрии и сторонних скриптов. Шрифты — системные.
- В репозитории нет ключей и личных данных; `.env` в `.gitignore` с первого коммита.

## 10. Критерии приёмки

1. `npm install && npm run dev` поднимает приложение на чистой машине с Node 20+; README описывает получение ключей и запуск в пять шагов.
2. Тест на вкладке: открыть в соседней вкладке немецкоязычное видео с речью, запустить захват этой вкладки — оригинал появляется на экране с задержкой не больше ~1 с, перевод предложения — не позже ~2 с после его окончания.
3. То же для английского видео при языке «Английский» и для смены языка при режиме «Авто».
4. Звук вкладки продолжает слышать пользователь (локальное воспроизведение не глушится).
5. Если галочка звука не включена — видна понятная ошибка из 5.2, приложение не зависает.
6. Критерий 2 выполняется и с Gemini, и с Claude; провайдер меняется на экране подготовки без перезапуска сервера и без правки кода.
7. С одним только ключом Gemini (без `ANTHROPIC_API_KEY`) приложение запускается и работает; Claude в списке провайдеров отсутствует. И наоборот.
8. Выбранные модели перевода и подсказок реально используются: это видно в логе сервера (имя модели, без текста запросов).
9. «Коротко» возвращает ответ на языке реплики не длиннее двух предложений и его русский перевод. «Подробно» на технический вопрос (например, „Wie erstellt man einen Indexer in Magento 2?“) возвращает суть, 3–5 пунктов и русский блок.
10. Отключение сети на 5 с во время сессии: статус «переподключение…», после восстановления расшифровка продолжается без перезагрузки страницы.
11. После «Стоп» индикатор захвата Chrome исчезает, соединение с Deepgram закрыто.
12. `npm test` проходит, тесты покрывают случаи из 6.2 и 7.1.
13. В логах сервера после сессии нет ни одной фразы из разговора.
